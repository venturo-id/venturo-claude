# Integration Guide

This guide explains how to use venturo-planner outputs with venturo-go and venturo-react plugins for full-stack development.

## Complete Workflow

```
1. Planning (venturo-planner)
   ↓
2. Backend Implementation (venturo-go)
   ↓
3. Frontend Implementation (venturo-react)
```

## Step 1: Planning with venturo-planner

### Generate Complete Design

```bash
/venturo-planner:new-feature
```

**Outputs:**
- `docs/database/erd/product_catalog.mmd` - Visual ERD
- `docs/database/dbml/product_catalog.dbml` - Schema definition
- `docs/database/migrations/20250123_product_catalog.sql` - PostgreSQL migration
- `docs/api/contracts/product_catalog.md` - API specification

### Review Generated Files

1. **ERD**: Visualize at https://mermaid.live
2. **DBML**: Import to https://dbdiagram.io for validation
3. **SQL**: Review migration for correctness
4. **API Contract**: Share with frontend team

## Step 2: Backend Implementation with venturo-go

### Use Planning Outputs as Reference

```bash
/venturo-go:new-feature
```

**When asked questions, refer to:**
- **Database schema**: Use DBML file
- **Entities**: Match ERD entities
- **API endpoints**: Follow API contract

### Verify Alignment

After backend generation, verify:
- [ ] Go migrations match PostgreSQL migration from planner
- [ ] Go entities match DBML schema
- [ ] Go API endpoints match API contract
- [ ] OpenAPI YAML generated by backend

### Example Comparison

**Planner DBML:**
```dbml
Table products {
  id VARCHAR(40) [pk]
  name VARCHAR(255) [not null]
  price DECIMAL(18,2) [not null]
  ...
}
```

**Go Entity (should match):**
```go
type Product struct {
    ID    string  `gorm:"type:varchar(40);primaryKey"`
    Name  string  `gorm:"type:varchar(255);not null"`
    Price float64 `gorm:"type:decimal(18,2);not null"`
    ...
}
```

## Step 3: Frontend Implementation with venturo-react

### Use Backend OpenAPI

```bash
/venturo-react:new-feature
```

**Provide:**
- OpenAPI YAML generated by venturo-go

### Verify Alignment

Frontend should match:
- [ ] TypeScript types match API contract
- [ ] API endpoints match API contract
- [ ] Request/response formats match
- [ ] Permissions match

### After Frontend Phase

## Common Issues and Solutions

### Issue 1: Database Schema Mismatch

**Problem**: Go migration doesn't match planner SQL

**Solution**:
1. Review planner DBML
2. Ensure venturo-go used correct data types
3. Verify audit trail columns present
4. Check indexes match

### Issue 2: API Contract Mismatch

**Problem**: Backend endpoints don't match API contract

**Solution**:
1. Review API contract from planner
2. Ensure venturo-go generated correct routes
3. Verify request/response DTOs match
4. Check permissions align

### Issue 3: Frontend Type Errors

**Problem**: TypeScript types don't match backend

**Solution**:
1. Ensure backend generated OpenAPI correctly
2. Verify OpenAPI matches API contract
3. Re-run venturo-react with updated OpenAPI
4. Check for optional vs required fields

## Best Practices

### 1. Always Start with Planning

Don't skip venturo-planner. It ensures:
- Database standards compliance
- Consistent schema design
- Clear API contracts
- Team alignment

### 2. Use Planner Outputs as Reference

When using venturo-go and venturo-react:
- Keep planner files open
- Compare generated code
- Verify alignment
- Update planner if requirements change

### 3. Iterate on Design

If you need to change the design:
1. Update planner files first
2. Regenerate backend/frontend
3. Keep all three in sync

### 4. Version Control

Commit planner outputs:
```
docs/
├── database/
│   ├── erd/
│   ├── dbml/
│   └── migrations/
└── api/
    └── contracts/
```

This provides:
- Design history
- Team reference
- Documentation

## Example: Complete Feature Flow

### 1. Planning

```bash
/venturo-planner:new-feature

Feature: product_catalog
Entities: products, categories
```

**Generated:**
- ERD showing products ↔ categories relationship
- DBML with proper indexes
- PostgreSQL migration with NO FK constraints
- API contract with CRUD + filters

### 2. Backend

```bash
/venturo-go:new-feature

Feature: product_catalog
[Use DBML and API contract as reference]
```

**Generated:**
- Go migrations (match planner SQL)
- Domain entities (match DBML)
- Repository layer
- Service layer
- HTTP handlers (match API contract)
- OpenAPI YAML

### 3. Frontend

```bash
/venturo-react:new-feature

OpenAPI: /path/to/openapi-product_catalog.yaml
```

**Generated:**
- TypeScript types (from OpenAPI)
- API functions
- React Query hooks
- Table, Form, Filters components
- Complete page with permissions

### 4. Verification

**Database:**
```sql
-- Planner migration
CREATE TABLE products (...);

-- Go migration (should match)
CREATE TABLE products (...);
```

**API:**
```markdown
# Planner API Contract
GET /api/v1/products

# Go OpenAPI (should match)
GET /api/v1/products

# React API call (should match)
productApi.listProducts()
```

## Summary

venturo-planner provides the **source of truth** for:
- Database schema
- API contracts
- Design standards

Use it as the **foundation** for backend and frontend development with venturo-go and venturo-react.
